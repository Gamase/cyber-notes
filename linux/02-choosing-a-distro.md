# Choosing a Linux Distribution

> Source: Linux Journey – Grasshopper L2 · 2026-11-16

## Key Points
- A Linux distro = Linux kernel + user space (GNU tools, package manager, desktop, apps), packaged together.
- A Linux system has 3 layers:
  - **Hardware**: CPU, memory, storage.
  - **Kernel**: manages hardware and connects it with software.
  - **User space**: where the user interacts (apps, shell, CLI).
- There's no "best distro"; it depends on what you value: ease of use, software freshness, stability, system control, or enterprise support.
- Release styles:
  - **Fixed release** (Debian, Ubuntu LTS, RHEL): stable, tested, older packages.
  - **Rolling release** (Arch): always up to date, but updates can break things.

## Reflections
- **Ubuntu (my start):** I started with Ubuntu 24.04 LTS, and it was probably the best choice I could have made at that moment. It was beginner-friendly and really stable; I didn't break anything. Still, learning concepts like the CLI, GNOME, Wine and open-source tools felt really strange at first.
- **Arch (my laptop):** I always wanted to try Arch Linux out of curiosity. Everyone said it was one of the most painful and challenging distros to install and use daily, but I didn't care. I like having maximum control over my system, and Arch lets you customize everything. The downside is that you literally build your system from scratch, so it took hours of grinding to get the setup I wanted. But once you get used to things like Hyprland, automation scripts, pacman, and all the knowledge Arch requires, it's really satisfying and worth trying.
- **Servers are different:** I used Ubuntu Server in a few school projects, but I didn't like it. On my home server I use Debian because it's very stable and its packages are well tested, which is exactly what you want on a server, so I'm getting used to it. In the future, I'd like to try Fedora because it's developer-friendly and gets new updates sooner.
